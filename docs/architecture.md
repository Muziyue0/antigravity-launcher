# 架构与证据边界

`Entry.cs` 是稳定入口：读取当前版本指针、约束路径并核对 EXE 哈希。`Bootstrap.cs` 负责首次配置、数据目录和官方 CLI 获取。`Launcher.cs` 提供主窗口、独立代理与 CLI 进程封装。`ParallelDetection.cs` 管理有界滚动队列；`RuntimeRecovery.cs` 提供运行中恢复；`Diagnostics.cs` 只汇总固定字段。

每个候选独立创建 Mihomo、回环端口、控制密钥与私有节点快照。原始配置只复制代理节点和组定义，不复制控制器、TUN、DNS 或订阅提供器。内核启动阶段串行分配端口并等待就绪，候选验证阶段最多三个并行。

第一层检查 Google HTTPS 204；第二层条款页地区识别为旁路提示，失败不阻塞；第三层调用官方 CLI，要求退出码 0、JSON SUCCESS、精确 AGY_OK 及该独立实例的 CLI/后台代理连接证据。语言服务存在或网页可达不能单独视作通过。CLI 默认模型与桌面选择可能不同。

胜出实例保留，其他候选收到取消并异步清理；已发出的模型请求仍可能产生额度消耗。桌面进程以 Chromium 代理参数与代理环境变量启动。NO_PROXY 仅排除回环通信；环境变量仅对本轮子进程设置。证据来自独立控制器的连接元数据，不检查 TLS 内容，因此不能直接读取具体模型请求的 HTTP 错误。

运行中恢复先从当前实例相同节点快照验证备用，随后更改原控制器 GLOBAL 选择，保持客户端使用的端口。通过原端口再次请求模型，失败用独立限时取消令牌回退原选择。用户手动恢复时，只关闭切换前已存在且同时匹配客户端/语言服务进程与模型域名的连接。自动切换只影响新连接，不主动断开旧通道。

连接元数据证明某进程使用代理；CLI 测试证明当时该 CLI 模型成功。两者都不能保证桌面所有后续请求成功。桌面实际回复仍需要用户确认。账号、资格、额度和未知故障不会被当成持续换节点的理由。

辅助内核、curl 和测试 CLI 通过 Job Object 管理；桌面主程序不加入辅助作业。主程序退出后等待检测取消、清理所有候选，再释放保留代理。强制进程终止会关闭辅助作业；硬断电可能留下私有临时文件。
